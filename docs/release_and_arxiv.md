# Release And arXiv Checklist

This repository keeps the working manuscript local while publishing the code,
curated evidence, and reproducibility tooling. The arXiv upload is assembled as
a self-contained source bundle from that local manuscript.

The archived software release for this manuscript is `v1.1.0`, available at
[doi:10.5281/zenodo.21318353](https://doi.org/10.5281/zenodo.21318353).

## 1. Validate The Repository

```bash
python3 -m ruff check src/depaysement_lab tests scripts
python3 -m pytest
```

Confirm that every result cited by the manuscript is present in the tracked
artifact map and that no model weights, local caches, credentials, or raw
unselected experiment spillover are staged.

## 2. Build The arXiv Source Bundle

```bash
python3 scripts/build_arxiv_bundle.py \
  paper/depaysement_frontier_draft.tex \
  --out-dir paper/arxiv_submission \
  --archive paper/arxiv_submission.zip \
  --repo-root .
```

The builder copies every `\\includegraphics` target into `figures/`, rewrites
the manuscript to use bundle-local paths, rejects unsupported external TeX
dependencies, emits SHA-256 provenance in `manifest.json`, and writes a
deterministic zip containing only `main.tex` and its figures.

Compile `paper/arxiv_submission/main.tex` from inside the bundle directory and
inspect the resulting PDF before uploading. Upload the zip only after the local
bundle compile matches the reviewed manuscript.

## 3. Publish The Software Release

1. Merge the release PR into `main`.
2. Confirm that `pyproject.toml`, `CHANGELOG.md`, and `CITATION.cff` use the same
   version.
3. Create the annotated tag and GitHub release `v1.1.0`.
4. Connect the public repository to Zenodo and wait for the release archive.
5. Record the version DOI in `CITATION.cff`, the README citation section, the
   GitHub release notes, and the manuscript's code-and-artifacts line.

Steps 1--5 are complete for `v1.1.0`; its version DOI is
`10.5281/zenodo.21318353`.

Do not move or retarget a published release tag. Corrections after DOI issuance
belong in a patch release.

## 4. Submit To arXiv

- Use the self-contained TeX bundle rather than the repository tree.
- Verify title, author, affiliation, abstract, license choice, and category
  metadata in the arXiv submission UI.
- Confirm every figure is included; an external repository link is not a
  substitute for a submitted figure.
- Preview the PDF generated by arXiv before the final submit action.
- After announcement, add the arXiv identifier to the README and to
  `preferred-citation` in `CITATION.cff`.
